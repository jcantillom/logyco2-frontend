- **Sesión persistente por cookie HttpOnly (2026-11-27).** Recargar, abrir otra pestaña o navegar por URL ya no lleva a `/login`: el backend fija una cookie HttpOnly y el frontend deja de manejar el token. `SessionStore` pierde el token (`hasToken`→`hasIdentity`, `setToken`→`markIdentity`, `expirationLabel`→`expiresAt` desde `session_expires_at`); `authInterceptor` ahora activa `withCredentials` y la cabecera anti-CSRF `X-Requested-With: LoGyCO2` en métodos que cambian estado; `SessionBootstrap` (inicializador) restaura la sesión con `GET /auth/me` antes de las rutas; `AuthFacade.logout()` llama `POST /auth/logout`; `CrossTabSession` sincroniza login/logout entre pestañas (BroadcastChannel con respaldo `storage`). Se elimina `SessionPersistence`, `AuthToken`/`toAuthToken` y la variable `SESSION_PERSISTENCE` (ya no hay token en `sessionStorage`). Backend: `docs/modules/auth.md` §13. Requiere en el `.env` del backend `CORS_ALLOWED_ORIGINS` con el origen del frontend y, en http local, `AUTH_COOKIE_SECURE=false`.
